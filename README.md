# 链上研究数仓：分叉可撤回的收块后端

从零实现的单文件 HTTP 后端（`server.py`），仅依赖 **Python 3 标准库**
（`http.server`、`sqlite3`、`json`、`threading`），持久化全部落在一个
SQLite 文件中。支持：收块、快照、续取，以及分叉时按批次原子撤回/重放。

## 目录结构

```
.
├── server.py                  # 后端主程序（HTTP + 业务规则 + SQLite 持久化）
├── README.md                  # 本说明
└── tests/
    ├── acceptance_helper.py   # 验收脚本共享辅助（拉起/强杀独立 server 进程）
    ├── test_late_parent.py    # 验收一：父晚到、占位父环、分叉撤回、并发
    ├── test_double_spend.py   # 验收二：分支双花、铸造、越界/超额、连带无效
    └── test_restart.py        # 验收三：重启恢复、SIGKILL 原子性、幂等重放
```

## 启动

```bash
python3 server.py <sqlite数据库路径> [host] [port]
# 例：
python3 server.py warehouse.db 127.0.0.1 8000
```

数据库文件不存在时自动初始化：写入空创世块 `G`（`parent` 为空串、
`work=0`、`txs=[]`，状态 valid），`version=0`，`tip="G"`，UTXO 集为空。
对已存在的库重复启动是幂等的，不会重复创建 `G`。

## HTTP 接口

所有请求/响应均为 JSON；非法请求返回 `400`，响应体形如
`{"error": "...", "path": "<JSON路径>"}`，路径以 `$` 表示根，数组使用
零基下标（如 `$.txs[0][1][2]`），JSON 语法错误路径固定为 `$`。
未知路径 `404`，方法不匹配 `405`（带 `Allow` 头）。

### 1. 收块 `POST /blocks`

请求体（仅允许这 4 个字段，多/少/重复键均 400）：

```json
{"id": "A", "parent": "G", "work": 2, "txs": [
  [["M", 0, 0]], [40, 60]]
]}
```

- `id` / `parent`：非空 ASCII 字母数字串（`[0-9A-Za-z]+`）；`id` 不允许为 `G`。
- `work`：正整数；**布尔值 `true/false` 不是整数，显式拒绝**。
- `txs`：有序的 `[inputs, outputs]` 二元数组。
  - 输入引用为三元组 `[块id, 零基交易号, 零基输出号]`，下标均为非负整数（拒布尔）。
  - 输出为非负整数金额数组（拒布尔、拒负数）。
- 空输入允许铸造，不受额度约束；有输入时输出总额不得超过输入总额。

**响应**：收块后的完整快照（200）。语义无效的块同样返回 200 并落库，
只是状态标记为 `invalid`；只有结构/类型层面的非法请求才返回 400 且不改状态。

### 2. 快照 `GET /snapshot`

```json
{"version": 3, "tip": "B",
 "utxos": [[["A", 0, 1], 60], [["B1", 0, 0], 40]]}
```

`utxos` 元素为 `[三元引用, 金额]`，按三元引用字典序排列。

### 3. 续取 `POST /fetch`

```json
{"after": 2}
```

`after` 为 0 至当前版本（含端点）的整数。响应：

```json
{"version": 3, "batches": [
  {"version": 3,
   "removed": [/* 旧链独有完整块，叶→根 */],
   "added":   [/* 新链独有完整块，根→叶 */]}
]}
```

`after` 等于当前版本时返回空批次。

## 核心语义

### 块状态（级联判定，每次收块结算一次）

每个块处于三种状态之一，持久化在 `blocks.status` 列：

| 状态 | 含义 |
| --- | --- |
| `pending` | 父链不齐全（父块尚未收到），等待晚到父 |
| `valid` | 父链齐全且从 `G` 逐交易解释通过 |
| `invalid` | 重复花费、引用越界、输出超额等语义错误；**后代连带 invalid**，但块仍保存 |

父可晚到：新块到达时会对该块及其全部后代做一次记忆化递归重判。
判定从 `G` 开始，沿父链继承 UTXO 集，逐笔交易：

1. 每个输入引用必须是本分支当前未花费输出（可引用本块较早交易的输出）；
   引用不存在、下标越界或同一交易/链内重复花费即整块无效；
2. 有输入时 `sum(outputs) <= sum(被引用输出金额)`，否则无效；
3. 通过后删除被花费输出，把本块新输出（含零金额）写入 UTXO 集。

### 环检测

插入新块前沿已保存块的 `parent` 链行走：若最终回到新块自身（自环、
或与“占位父”待定块互相指回），返回 400 且**不落库**。仅缺父但不成环的，
作为 `pending` 保存。

### tip 选择与版本批次

- 在所有 `valid` 块中选**累计 work 最大**者为 tip；累计 work 相同取
  ASCII 字典序最小的 id。
- 仅当 tip 实际改变时 `version += 1`，并写入一行批次
  `{version, removed, added}`：
  - `removed`：旧 tip 链相对新链的独有块，**叶→根**撤回；
  - `added`：新 tip 链相对旧链的独有块，**根→叶**加入；
  - 批次项是完整块对象（`{id,parent,work,txs}`）。
- tip 不变（收到无效块、不影响排名的侧链、同结构重传）时不产生新版本。

题目示例（空交易块 A、B 父皆 `G`，work 2、3，先 A 后 B）产生的第 2 批为
`removed=[A]`、`added=[B]`，已在验收脚本与手工复现中验证。

### 幂等

同 id 同结构重传直接返回当前快照，不写任何状态；同 id 异内容返回 400。
按块 JSON 规范化序列化后逐字节比对。

## 持久化与并发

- 四张表：`meta(version,tip)`、`blocks`、`batches`、`utxos`（当前 tip 集）。
- 每次收块在**单个 SQLite 事务**（`BEGIN IMMEDIATE` … `COMMIT`）内完成
  插入、级联判定、tip 选择、批次写入与 UTXO 表整体重写；任何异常都
  `ROLLBACK`。配合 `synchronous=FULL` 与默认 rollback journal，进程在
  提交前后任意时刻强退，重启后只能看到完整的旧态或完整的新态，不会出现
  半提交数据。
- 进程内用一把可重入锁串行化所有写请求；SQLite 单连接 +
  `check_same_thread=False`，多线程 HTTP 服务下执行效果等价于串行。
- 重启后从库中恢复全部状态，待定块仍可在父块晚到后继续级联生效。

## 运行验收

三套验收互相独立，各自在临时目录创建独立数据库并拉起独立 server 子进程
（以 `python3 -I` 隔离模式运行，避免工作目录植入模块干扰）：

```bash
python3 -I tests/test_late_parent.py    # 38 项：父晚到/环/A-B 分叉/并发串行/400 矩阵
python3 -I tests/test_double_spend.py   # 25 项：铸造/双花/越界/超额/连带无效/平局
python3 -I tests/test_restart.py        # 17 项：重启一致/SIGKILL 原子/幂等重放
```

全部通过时各打印 `… 验收通过（N 项检查）` 并以退出码 0 结束。

## 设计取舍

- 每次收块对“新块 + 全部后代”做记忆化递归求值，并对全量块补算一次以选
  tip；未受影响的链因记忆化只产生一次字典查询，规模在验收与压测范围内
  完全够用，且实现直接、不易在增量维护中产生状态漂移。
- UTXO 快照只持久化当前 tip 的集合；历史 tip 的 UTXO 可由其链上区块
  确定性重算，批次表已保存链差异所需的完整块。
